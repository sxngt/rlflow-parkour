# P2-17 실제 비행 거리 보상 비중

주요 실행 전 고정한 개발 실험. P2-16의800/1200/1600checkpoint 모두에서15cm 목표 성공이 없었다. 최종 seed0/2는 최초 접촉과 안정화를 충족하면서도 비행 이동이 부족했다. 반면 seed1/3은 별도의 지지·첫 접촉 문제가 남아 있다. 관측한 checkpoint 학습률과 actor 변화에는 모든 퇴화를 설명할 공통 급증 증거가 없어 학습률 원인으로 단정하지 않는다.

가설: 기존 최초 착지 시 실제 비행 이동 보상의 가중치를4에서12로 높이면 동일 계산 예산에서15cm 목표의 비행 이동 부족을 줄일 수 있는가? 최초 접촉 정밀도와 착지 안정화가 악화하지 않는가?

변경은 jump.travel_reward_weight 하나다. 기존 `12*exp(-abs(actual_flight_distance-command)/0.03)` 보상은 검증된 출발 후 최초 착지에서 한 번만 지급하며 실패에는 지급하지 않는다. 기존 weight4 수식과 지급 시점은 같다. 새 보상 항·속도 참조·관측은 추가하지 않는다. 가중치12는 검증할 단일 실험값이며 최적값 주장이 아니다.

seed0–3 fresh PPO,1024환경×24step×1600update,run당39,321,600step,추가157,286,400step. P2-16의 거리0–5→0–10→0–15cm 및 출발반경6→4.5→3cm 커리큘럼,로봇·지형·calibration·관측·행동·기타보상·PPO설정은 그대로 유지한다. 기존weight4 4seed 결과를 같은예산 대조로 재사용하며 동시무작위 실험으로 표현하지 않는다.

최종 동일64개 개발episode(0/5/10/15cm×16높이명령),출발반경3cm,15cm의 최소실제비행12cm 및 기존최초접촉·안정화 기준을 그대로 적용한다. 목표거리별성공/비행이동/첫접촉/안정화/지지면 포함과seed별변동을 함께보고한다. 보상을높여rawreturn이늘어나는것을성능개선으로해석하지않는다.

64개 렌더링+camera-side4,200Hz진단,result 상세제목,phase:P2 및 step:p2-17-travel-weight 태그. 실패seed교체·예산연장·성공기준완화는하지않는다. 새로운코드경로는없으며 기존 TravelLandingReward 단위검사와 config 차이검증을주요실행전에확인한다. 이실험은넓은발판도약이며갭/Planner완료주장이아니다.
