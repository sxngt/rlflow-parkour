# T0S v2: 보정된 자세에서 순차 발 디딤

2026-09-10. T0 v1과 별개의 task/관측 계약이다. v1 checkpoint를 v2 resume로 사용하지 않는다. 불연속 지형이나 점프 과제는 아직 아니다.

## 바뀐 기준

이전 v1의 목표 기준은 USD를 처음 올렸을 때의 기구학적 발 위치여서 실제 PD 정적 평형과 차이가 있었다. v2는 시뮬레이션에서 기본 관절 위치 명령으로 300 physics step(1.5초)을 실행하고, 네 발의 지지가 확인된 실제 root pose·joint pose·발 XY를 보관한다. reset은 이 보정 상태로 수행한다. 보정 비용은 setup에 포함하고 PPO 환경 step으로 세지 않는다.

목표는 각 발의 초기 지지점에서 전방 4~7cm, 좌우 ±1cm다. 네 발에 한꺼번에 새 목표를 주지 않고 **FR → RL → FL → RR** 순서로 하나씩 갱신한다. 완료한 발의 목표는 유지한다. 학습·평가는 평지에 한정한다.

## 접촉 상태 기계

각 발은 다음 조건을 순서대로 통과해야 한다.

1. 해당 발의 실제 접촉을 먼저 관측한다.
2. 초기 0.5초 안정화 이후, 접촉이 끊기고 발 구 중심이 지면 기준 기본 2cm보다 **3.5cm 이상** 높아진 상태를 2 control step 유지한다. 다른 발 중 적어도 둘이 지지해야 한다.
3. 목표 XY 2.5cm 이내, 발 구 중심의 높이가 표면+2cm에서 ±2.5cm 이내, 수직 접촉력 hysteresis가 활성인 상태를 **0.08초** 유지한다. 다른 두 발 이상의 지지를 요구한다.
4. 해당 접촉을 1회 기록하고 다음 발로 전환한다. 네 번 완료하면 성공이다.

XY만 일치하거나, 공중으로 reset된 발을 착지시키거나, 발을 미끄러뜨리기만 해서는 lift→place를 완료할 수 없다. 실제 접촉면 ID 판정은 아직 없고 평면 높이·수직 힘으로 검증한다.

## 입력·행동·보상

- v1의 61개 관측 뒤에 active foot one-hot 4, lift/place one-hot 2, 진행률 1, 안정화 진행률 1을 추가한 **69차원**.
- 행동: 기본 관절 참조 + clipped action ×0.5 rad. motor torque/velocity 한계는 유지.
- Lift 단계에서는 active foot의 목표 높이를 접촉 목표보다 5.5cm 높인 참조로 추종 보상을 계산한다. Place 단계에서는 실제 접촉 목표를 사용한다.
- 다른 발의 지지 위치, 자세, 각속도, 행동 변화, 토크에 비용을 준다. lift +1, place +3, 완주 +5, 실패 -30. 현재 계수는 파일럿 설계값이며 버전으로 고정한다.
- 성공/실패는 termination, 12초 제한은 truncation. PPO는 timeout bootstrap을 사용한다.
- 정답 root state와 접촉 합력을 사용하는 sim-only 과제다. 이력 적응이나 센서 절제 연구는 아니다.

## 실험 예산

`configs/t0-sequential-ppo.json` 기준으로 독립 seed 0~3, 각 1024 env ×24 steps ×800 PPO updates를 첫 파일럿 예산으로 둔다. seed당 19,660,800 PPO 환경 step이다. 초기 debug와 zero-action 평가는 별도 실행으로 분리한다.

개발 시나리오는 seed 10000~10063을 고정하고 실제 모든 첫 episode를 평가한다. 주요 지표는 **완주율·평균 완료 접촉 수(0~4)·실패율**이다. v1과 과제·성공 기준이 달라 평균 XY 오차를 직접 비교하지 않는다.

## 평가 영상 정리

`run_job.py`로 실행한 영상 포함 평가가 정상 완료되고 GPU가 회수되면 `collect_results.py`가 `result/`로 MP4를 복사하고 hash를 확인한다. 제목·학습 실행·seed·업데이트·평가군·영상 시나리오·개별 종료 결과를 기록한다. 전체 평가 결과와 첫 시나리오 영상 결과를 구분한다.

`result/README.md`가 전체 목록이며 각 하위 폴더의 README에 썸네일, 영상, 전체 지표, 원본 링크가 있다. `result/`는 대용량 산출물 폴더로 Git에서는 제외하지만 파일은 로컬에 보존한다. 원본은 `artifacts/`에 유지한다.
