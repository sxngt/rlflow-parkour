# P2-36: 동일 deck에서 단일 목표 과제 혼합으로 능력 유지

P2-35에서 관측한 학습 중 능력 소실을 줄일 수 있는지 검증한다. 이번 조작은 단일 목표 과제의 혼합이며, continuous 지형을 함께 학습하는 실험은 아니다. 두 조건의 물리 지형은 동일 deck으로 고정하고 continuous/split은 회귀 평가에 사용한다.

## 사전 고정 비교

- 부모: P2-31 mixed seed0~3 checkpoint800, 실패 seed3도 포함. P2-35에서 발견한 좋은 중간 checkpoint를 부모로 선택하지 않는다.
- A: 1024환경 모두 15→30cm 두 도약. P2-34 chain-only 800update 결과를 재사용하고 그 사실을 표시한다. 새 코드의 A 동작 일치 검증을 착수 게이트로 둔다.
- B: 같은1024환경 중 ID0~511은 두 도약, ID512~1023은 단일 도약. 단일 과제 목표는 매 reset에서 0 또는15cm를 같은 확률로 현재 정책에 제시한다. 정적 ID 분할로 각 update의 step 비율을 정확히50:50으로 고정한다. episode 수와 성공 수는50:50일 필요가 없다.
- B도800update×1024환경×24step, seed당19,660,800step. 신규 본학습4개 총78,643,200step. A의 기존78,643,200step은 재사용 계산이며 새 계산량으로 더하지 않는다. 파일럿 예산은 별도다.
- policy/critic/normalizer는 부모에서 복사, optimizer/RNG/update는 새로 시작한다. PPO·탐험 스케줄·보상 계수·관측66차원·PD·출발/착지 기준은 P2-34와 동일하다. 하나의 PPO rollout과 공유 normalizer를 사용한다. 과제별 추가 손실 가중치나 privileged task ID를 넣지 않는다.

## 종료 및 수집 계약

단일 과제는 성공 시 실제 episode 종료, 최대4초다. 두 도약 과제는 첫 성공에서 목표와 도약별 기록만 갱신하고 물리 상태를 유지한다. 첫 성공은 done이 아니며 두 번째 성공만 전체 성공이다. 각 도약 최대4초, 코스최대8초다. 단일 과제 성공을 중간 성공으로 잘못 처리하지 않도록 환경별 요구 도약 수를 사용한다.

오래된 실패 궤적을 replay로 넣지 않는다. 각 환경은 현재 정책으로 새 데이터를 수집한다. 혼합으로 두 도약 step이 절반으로 줄어드는 것도 방법의 전체 효과에 포함하며 같은 두 도약 노출량이라고 주장하지 않는다. task×hop step, task별 종료·성공·보상, 단일 목표별 step/reset draw를 기록하고 총 PPO step과 합계를 검증한다.

## 실행 전 검증

1. 환경별 요구 도약 수·4/8초 deadline·비동기 reset·실패 우선순위 단위 검증.
2. strict 혼합 설정, fork 및 resume 계약 검증. 평가의 명시적1/2hop override는 학습 혼합을 끄고 기존 평가와 동일하게 동작해야 한다.
3. 학습 코드 A 조건이 기존 cp0 평가와 일치하는지 확인. B64환경 smoke, 저장·재개, 유한 PPO update와 task/hop 합계 검증.
4. B1024환경60update 파일럿으로 메모리/처리량과 실제 두 번째 도약 노출을 확인. 파일럿에서 성공이 없다고 종료 기준을 느슨하게 바꾸지 않는다.
5. 위 게이트 통과 후 부모에서 본학습 새 fork. 아직 이 문서를 작성한 시점에는 본학습을 시작하지 않았다.

## 평가와 판단

P2-34와 같은 개발 시나리오로 deck 두 도약64, deck 단일15cm64, continuous0/5/10/15cm각16, split15cm64를 각 seed에서 평가한다. 총16개 최종 평가다. 200/400/600checkpoint는 보관하되800 고정 결과를 대체하지 않는다. 200Hz 진단·64render/camera4·상세 제목 result영상·phase:P2/step:p2-36-single-task-retention 태그를 남긴다.

우선 판단은 seed별 두 도약 완주와 기존 거리 회귀의 공동 비교다. seed별 결과를 모두 공개하고 같은 시나리오의 paired 변화, 계산 시간과 실제 과제 노출을 함께 보고한다. 혼합이 개선될 것을 보장하지 않으며 부모의 미해결 seed가 해결된 것으로 가정하지 않는다.
