# P2-34: 현재 정책이 만든 착지 상태에서 이어지는 PPO 학습

질문: 동일한 추가 환경 step 예산에서 두 도약을 실제 물리 상태 그대로 연결해 학습하면, 정적 초기상태의 단일 도약 추가 학습보다 두 도약 완주가 개선되는가? 기존 단일 도약 능력은 유지되는가?

## 고정 예산 및 비교

- 부모는 P2-31 seed 0~3의 checkpoint-000800. seed별 동일 부모로 두 조건을 새로 초기화한다. policy/critic/normalizer만 복사하고 optimizer/RNG/update는 새 실험으로 시작한다.
- A: 동일 재질 deck에서 고정 15cm 단일 도약, episode 4초.
- B: 같은 deck에서 고정 15→30cm 두 도약, episode 최대 8초. 첫 도약 성공 후 물리 상태를 보존하며 두 번째로 진행한다. 첫 도약 실패 시 두 번째를 강제로 시작하지 않는다.
- 각 조건×4 seed×800 update×1024 env×24 step. 총 신규 157,286,400 환경 step. GPU 시간과 첫/두 번째 도약에 실제 소비된 step을 별도로 보고한다. 같은 wall-clock 예산이라고 주장하지 않는다.
- PPO/보상 계수/관측/행동/출발 및 착지 판정/normalizer/탐험 스케줄은 부모 기반 설정으로 고정한다. 두 조건 모두 기본자세 준비 0.3초를 사용한다. P2-33 명령 유지 실험은 채택하지 않는다.
- B의 첫 성공 보상은 기존 도약 성공 보상을 한 번 지급하지만 episode done은 아니다. advantage/return은 다음 도약으로 이어진다. 종료 성공 지표는 전체 코스 성공이다. 첫/두 번째 도약별 보상·성공과 전체 코스 지표를 구분한다.

## 초기 상태와 데이터 계약

저장된 과거 궤적을 PPO replay로 섞지 않는다. 매 학습 rollout에서 현재 정책이 직접 첫 도약을 수행하여 두 번째 초기 상태를 만든다. 따라서 실패 후 비정상 상태를 강제로 reset하는 데이터셋은 필요하지 않다. 이전 접촉 history/몸체 속도/관절/직전 action/물리 시간을 유지한다. 첫 성공 후 변경되는 것은 목표와 도약별 판정 상태 및 시계다. 초기 정적 reset은 episode 시작에만 허용한다.

고정 15cm 조건으로 편중될 수 있으므로 원래의 0/5/10/15cm 단일 도약 회귀를 반드시 평가한다. 이 비교는 두 도약 학습 조건의 전체 효과이며 episode 길이 및 학습 상태 분포 변화를 완전히 분리하는 실험은 아니다.

## 착수 게이트

1. 명시적 chain_training 설정 검증 및 resume 계약 비교. 임의 episode/보상 변경을 fork 예외로 허용하지 않는다.
2. 작은 학습 smoke에서 첫 성공 후 done 억제, 보상 일회 지급, PPO update 유한값 및 실제 두 번째 도약 step 수 확인.
3. checkpoint 저장·재개, 1hop/2hop 평가 어댑터와 정책 계약 호환 확인.
4. 호스트/GPU 처리량을 측정하고 4개씩 두 묶음으로 실행한다. 학습 중 event 목록을 무제한 축적하지 않는다.

최종: 두 도약 기본준비 평가 64개, deck 단일 15cm 평가 64개, continuous 0/5/10/15cm 각16개, split15cm 64개. 기존 P2-32 부모 결과는 재사용 표시한다. 각 실행 phase:P2/step:p2-34-chain-training 태그와 상세 제목의 result 영상(render64/camera4), 원시200Hz 진단 및 checkpoint 계보를 남긴다. 신규 학습 코드 검증 전에는 본학습을 시작하지 않는다.
