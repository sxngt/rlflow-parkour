# P2-11 · 출발 범위 커리큘럼

P2-10의 네 seed는 모두 몸체 상승3cm를 넘지 못해 유효 비행0/64였다. 처음부터 엄격한 출발 조건 대신 비행 획득 후 범위를 좁히는 가설을 검사한다.

새 정책 seed0–3, 전이 없음. 1–800업데이트6cm,801–1200업데이트4.5cm,1201–1600업데이트3cm. 조건 전환은 PPO 업데이트 사이에서 수행하며 모든 환경을 reset한다. 미완료 episode는 버리고 성공/실패 통계에 넣지 않는다. 두 전환에서 초기화 비용이 추가됨을 기록한다. 학습 조건은 중간 성능으로 변경하지 않는다.

나머지 설정은 P2-10과 동일:0–15cm 명령, 비행거리 보상4,1024환경×24step×1600updates. 각39,321,600step, 합157,286,400step. checkpoint에는 완료 update와 다음 rollout 반경 및 전환 계약을 저장한다. 복구는 같은 config와 schedule 상태를 검사하며 episode 경계에서 재개한다.

평가에는 커리큘럼을 적용하지 않고 config의 최종3cm 반경을 쓴다. 고정0/5/10/15cm 각16개와200Hz 진단,16로봇 MP4. P2-10 및 P2-09-strict와 같은 평가조건에서 비교하며 제자리 회귀도 보고한다. trace episode3 사전 선택. 실제 갭·Planner·실기 검증은 아니다.

진행 전 일정 경계·잘못된 스케줄 단위 검사와64환경3update 실행 및 checkpoint 재개를 검사한다. 짧은 검사는 학습 성능 증거가 아니다. 실패 시 같은 실험을 무한 연장하지 않는다.
