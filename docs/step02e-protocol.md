# P1 · Step 02e — 네 발이 공유하는 단독 이동 Tracker

2026-09-11 사전 프로토콜. Step 02d의 평가·자원 회수 후 실행한다. 지금까지는 발마다 별도 신경망을 학습했다. 이후 순차 실행을 위해서는 하나의 정책이 서로 다른 활성 발과 목표를 처리해야 하므로, 단독 발 이동 단계에서 공유 정책의 실행 능력을 확인한다.

## 과제 계약

v7은 매 episode FL/FR/RL/RR 중 활성 발 하나를 균등 추출한다. 해당 발만 기존 분포(앞으로 4–7cm, 측방 ±1cm)의 목표로 이동하고 나머지 세 발은 초기 위치 목표를 유지한다. 1회 들기·착지 후 기존 최종 안정화 판정을 적용한다. 기본 보상 A(v4)를 유지하며 B/C 추가 정렬 벌점은 사용하지 않는다. 관측 69차원은 현재 활성 발 one-hot을 포함한다. 별도 발별 네트워크나 발별 optimizer는 사용하지 않는다.

환경별 episode 발 순서를 보관하고 reset 시 해당 환경만 갱신한다. 평가에서는 시나리오 명세가 활성 발을 고정해 실행하며, reset 직후 임의 추출한 활성 발에 평가 목표를 잘못 적용하지 않는지 검사한다. 기존 v2~v6의 고정 발 순서는 유지한다.

## 학습·평가 예산

seed 0/1/2/3, GPU당 1run, 각각 1024환경×24step×1600updates를 처음부터 학습한다. 신규 총157,286,400 환경 step. 단독 발 조건과 학습 분포·발당 노출 수가 다르므로 이전 개별 정책 대비 순수한 알고리즘 효과를 주장하지 않는다. 이번 단계는 공유 제어기 기준선 파일럿이다.

평가 seed 10000부터 256개 개발 시나리오, 활성 발은 index mod4로 배정해 각 발64개를 평가한다. 지형은 동일 평지, 마지막 checkpoint의 deterministic 행동을 평가한다. 학습 중 reward/예산/성공 기준 변경 없음. 총 성공과 발별 성공·착지·낙상/timeout을 모두 보고한다. 200Hz 진단, 고정16대격자(각 발4대)의 MP4, 상세 제목 result 보관과 계보 감사를 수행한다.

## 검증·판단

합성 검사는 서로 다른 환경의 활성 발 선택·목표 배정·reset 독립성·최종 단계 유지·완료 접촉 최대1을 확인한다. 기본 과제의 회귀 검증을 먼저 수행한다. 시나리오 단위 검사는 균등 발 배정과 재현 가능한 생성 규칙을 확인한다.

발별 실패가 남으면 집계 성공률로 숨기지 않는다. 네 발 모두 실행 가능성이 확보되면 순차 연결을 별도 버전에서 진행하며, 그렇지 않으면 활성 발/단계별 경험과 실패 조건을 분석한다. 특정 성공 seed 하나로 일반적 재현성이나 순차 파쿠르 성공을 주장하지 않는다. 모델 자동 승격 없음.
