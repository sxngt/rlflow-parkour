# P2-00 · A1 충돌 설정 및 센서 검증

2026-09-11. `scripts/collision_probe.py`로 64환경씩 self-collision off/on을 별도 프로세스에서 실행했다. 각 케이스는 의도적 상태 주입 검사이며 학습 성능 결과가 아니다.

| 케이스 | self-collision off: 비발 합력 >5N | on: 비발 합력 >5N |
|---|---:|---:|
| 정상 기본 자세, 1초 | 0/64 | 0/64 |
| 지상 3m에서 관절 범위 내 무작위 자세, 50ms | 0/64 | 1/64 |
| 몸체를 지면에 겹치도록 주입, 50ms | 64/64 | 64/64 |

USD의 실제 `/World/envs/env_0/Robot/trunk` articulation attribute가 요청한 off/on과 일치했다. 두 프로세스의 관절 자세 표본은 수치적으로 동일하다. 공중 검사의 모든 body 중심은 지상 2.64m 이상으로 지면 접촉과 분리됐다. 따라서 on에서만 나타난 해당 접촉 신호는 내부 접촉을 관측할 수 있는 하나의 양성 사례다. 모든 내부 충돌을 탐지한다는 증거는 아니다.

정상 자세의 발 접촉은 두 설정 모두64/64에서 존재했고 비발 접촉은 없었다. 따라서 현재 기본 자세에서는 self-collision on 때문에 지속적인 비발 충돌이 생기지는 않았다. 몸체 겹침 검사는 매우 비정상적인 초기 상태이며 실제 착지 충격량이나 허용 구동기 성능으로 해석하지 않는다.

## 새 동적 과제의 결정

- 새 과제에서 self-collision을 켠다. 기존 P1 설정과 모델은 변경하지 않는다.
- 발 이외 모든 관측 body의 합력 크기가5N을 초과하면 실패로 처리한다. 기존의 trunk 전용 조건보다 범위가 넓다.
- 이 조건은 접촉 pair를 완전히 식별하지 않는다. 힘의 상쇄·임계값 이하 접촉·발끼리의 접촉 등은 합력 검사만으로 완전하게 분류할 수 없다. self-collision 물리는 켜되 모든 내부 접촉 검출을 주장하지 않는다.
- 구동기 effort/saturation33.5Nm, velocity21rad/s 및 기존 PD 설정은 유지한다.

원본은 `artifacts/p2-00-collision-{off,on}/collision-probe.json`. 관절 이름·자세·한계·body별 peak force·실제 USD 설정·보정 상태를 포함한다. 두 run의 artifact hash·GPU UUID 격리·자원 회수 감사를 통과했다. 모니터링에서는 `P2 / P2-00·동적 접촉 계약 / 구현 검증`으로 조회한다.
